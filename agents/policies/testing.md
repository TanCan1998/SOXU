# 测试规范与完成定义（Agent 强制）

## 分层

1. **单元测试**：任何纯逻辑（会话状态机、模型解析、路径守卫、恢复阶段）应使用确定性的模拟输入，零外网、零模型调用。
2. **集成测试**：使用假的 Pi RPC、独立临时 Git 仓库和受控进程树模拟超时/退出；覆盖成功、异常、中断、重复恢复。
3. **桌面端测试**：Vue 组件交互、无障碍、键盘访问、资源释放；核心 Pi RPC 冒烟与 Windows/macOS/Linux 适配。
4. **性能回归**：在同硬件同会话夹具下采样启动、进程树 RSS、长列表滚动/内存；输出硬件、版本、步骤与原始数据。

## 开发者在交付前必须

- 每个 PR 关联一个 Issue，列明非目标、验收点和风险；范围外修改另开任务。
- 跟随改动补对应测试；修复 Bug 先构造失败回归用例，再提交修复。
- 执行 `pnpm check`、`cargo fmt --all -- --check`、`cargo test --workspace`、`git diff --check`（可运行环境下）；平台缺失须列明 **未验证**，不得伪造通过。
- Reviewer 独立检查边界、安全、生命周期、跨平台；测试与审查针对**同一 Git tree**，在提交/推送前再次确认。
- UI 修改需要截图或演示、无障碍验证、与已审批的 UI 设计对应；设计本身未批准时只允许隔离的原型。
- 新依赖记录必要性、License、包体与运行时资源影响；涉及根目录锁定版本需所有者先批准。
- 文档：用户体验改变时同步 README 中文与英文；架构变化同步 ADR；关键操作命令可直接复制执行。

## 禁止的“完成”说法

未经实机测试不得说“跨平台已通过”；未经同条件测量不得说“内存节省 X%”；未经 CI/Review 不得宣称“可自动发布”。
