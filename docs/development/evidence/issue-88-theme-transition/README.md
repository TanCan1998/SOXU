# Issue #88 · 主题切换圆形扩散 + 发光涟漪：实机证据

- 采集日期：2026-10-29
- 采集对象：本工作树 `apps/desktop` 的 Vite 预览（`pnpm --filter @soxu/desktop dev`，`http://127.0.0.1:1420/`），
  即 `App.vue` + `src/theme/themeTransition.ts` + `src/styles/base.css` 的真实运行结果
- 浏览器：Microsoft Edge 156.0.4314.50（Chromium，headless=new），视口 1280×860，DPR 1
- 交互：CDP `Input.dispatchMouseEvent` 在主题按钮中心 **(69, 831)** 派发真实鼠标点击
- 采集：`Page.startScreencast`（PNG，60fps）逐帧落盘；像素统计在浏览器内用 canvas `getImageData` 完成

## 复现步骤

```powershell

pnpm --filter @soxu/desktop dev

```

## 关键实现发现：光晕为什么必须"滞后"

排查过程中用同一套像素分析做了对照实验，结论如下（实验均在上述 Edge/视口下进行）：

1. **普通层元素 100% 不可见**：把同样样式的光晕节点放在 `body` 普通层，蓝色像素数与基线完全相同
   （10414 → 10414），说明它被页面内容完全盖住。
2. **popover（top layer）在过渡期间也不可见**：`showPopover()` 成功、`:popover-open` 为 true、
   计算样式里 `box-shadow` 正常、动画 `currentTime` 在推进，但把节点插到 `transition.ready` 之后、
   且位于尚未揭开的区域时，蓝色像素数仍是基线（10602 vs 10414）。
3. **落在已揭开区域内才可见**：同一节点位于新快照已经覆盖的圆形区域里时，就会出现在画面上。
4. **同一套分析对"跑在边缘外侧"的光晕完全检测不到**：把滞后量设为 0 重跑整段采集，
   两个方向的每一帧都没有出现蓝色光晕带；改成 30ms 滞后后立刻出现上表里的光晕带。

也就是说 View Transitions 的快照始终压在 top layer 元素之上，只有"已经揭开"的部分才透出光晕。
第一版实现里光晕动画比扩散边缘早启动约几十毫秒，一直跑在边缘外面，于是**完全看不见**——
这也是最初三条视觉验收无法靠肉眼/截图确认的根因。

修复方式：把光晕动画整体延后 `THEME_GLOW_LAG_MS = 30ms` 并压缩到与扩散同时结束
（`--soxu-theme-glow-delay` / `--soxu-theme-glow-duration`，由 `themeTransition.ts` 写到 `:root`），
让光晕始终追在边缘内侧。上表"边缘-光晕间距"就是该修复的效果：从早期 264px 收敛到 4–30px。

## 未覆盖 / 风险

- 只在 Windows + Chromium（Edge 156）验证；macOS/Linux 与 WebKit 系未验证。
- 帧时间戳来自 screencast，早期几帧（t<50ms）在 headless 下可能合并，故 0–50ms 的光晕位置未单独断言。
- 光晕的滞后量是经验值（30ms）。扩散动画的启动延迟随页面复杂度/机器性能变化，若未来首帧成本明显上升，
  光晕可能重新跑到边缘外而不可见；届时需要重新采集并按上表方法校准。
