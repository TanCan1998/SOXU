# SOXU UI/UX 设计审批方案（非正式界面）

**状态：等待确认。** 当前正式 `apps/desktop/src/App.vue` 不修改；`uiux-preview.html` 是纯静态、可点击切换的视觉提案，不代表已接入 Pi/Git/Tauri。

## 设计原则

- **以会话为中心**：左侧窄导航 + 项目/会话列表、中间对话主舞台、右侧随需展开的执行检查器。
- **Agent 生命周期一目了然**：活动、审核中、暂停、额度不足、等待批准等状态附中文文字，不依赖单纯颜色。
- **低内存优先**：消息虚拟滚动、日志最多保留窗口、隐藏面板按需加载，避免对每条 Token 重渲染整个对话。
- **键盘优先**：`Ctrl+K` 命令面板、`Ctrl+L` 新对话、`Ctrl+Enter` 提交；快捷键可以在设置里自定义，防冲突。
- **审批边界**：危险操作需要显式用户确认；Agent 可在守卫范围内自动执行代码任务，但不会把停止、强推、删改工作树做成随意一键操作。
- **跨平台**：Windows/macOS/Linux 先共用设计 token；系统窗口控件及安全区使用平台适配。

## 推荐布局 A：工作流型三栏（默认提案）

| 区域 | 桌面宽度建议 | 主要功能 |
|---|---:|---|
| 极窄功能栏 | 64 px | 对话、Agent 队列、工作树、插件、设置 |
| 会话导航 | 228 px | 项目切换、搜索、会话、过滤 |
| 对话中央 | 弹性（≥480 px） | 消息、工具调用、输入框、附件 |
| 可折叠右侧检查器 | 280–320 px | Agent 步骤、审查、任务、Git Worktree、资源占用 |
| 底部状态区 | 26–32 px | 当前模型、Token/费用显示条件、延迟、活跃子进程数 |

窄屏下右侧检查器应折叠为抽屉，会话导航可以隐藏；避免固定三栏挤压编辑区。优先支持深色，但必须保留浅色与跟随系统两种主题。

## 交互验收项

1. 导航切换时保留当前会话草稿及输入焦点；项目切换必须确认未保存更改的处理方式。
2. 一条 Agent 任务可以展示进度、失败原因、继续操作入口、工作树分支及审核证据；恢复按钮不自动重复付费模型调用。
3. 工具输出默认折叠，错误和失败退出码可快速定位；长对话复用窗口化渲染。
4. 审查区应明确区分“测试通过”“审查通过”“已提交”“已合并”“已发布”。
5. 响应式断点、动态文本和系统字体缩放满足可读性，键盘/屏幕阅读器可操作。

## 待审批选项

- **布局 A（推荐）**：窄功能栏 + 会话列表 + 对话主区 + 可折叠检查器，适用于多项目与多个 Agent 并行。
- **布局 B**：双栏简洁型，把检查器做成独立抽屉，适用于低分辨率笔记本。
- **布局 C**：IDE 型，把文件树 / Diff 设为主舞台，适用于以代码审查为核心的工作流。

视觉候选：**深色低饱和灰蓝 + 青绿状态强调**，辅以浅色主题；默认保留原生感，避免重拟物、全局毛玻璃与复杂动画。

请审核布局、视觉风格及三栏是否保留右侧检查器。确认后再改写正式 Vue UI 组件，并建立 `packages/ui` 设计 token 及交互测试。
